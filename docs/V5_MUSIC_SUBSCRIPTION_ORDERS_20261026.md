# V5 음악 구독 주문·영수증·자격 연결

2026-10-26 · 구독 계량 코어 후속 구현

## 처리 목적

DAILY FREE의 음악 구독 구매를 일반 TL 충전과 분리한다. 구독 결제로 지갑 TL을 지급하지 않으며, 서버가 정한 상품·가격의 주문, 검증된 PG 영수증, 일일 청취 자격을 연결한다. 실제 결제에 대한 구매 기여만 기록한다.

## API

| 경로 | 기능 |
| --- | --- |
| GET /api/payment/v5/music/products | 상품·결제 연결 모드 조회. 사용자 체크아웃 화면은 아직 비활성 |
| GET /api/payment/v5/music/status | 로그인한 본인의 실운영 자격·일일 잔여시간 |
| POST /api/payment/v5/music/prepare | 상품등급·요청키·약관 동의로 주문 준비. 클라이언트 가격을 받지 않음 |
| POST /api/payment/v5/music/confirm | 본인 주문번호·PG 결제키·금액을 서버 원본과 대조하고 Toss 서버에서 승인 검증 |

결제 모드는 서버 환경의 MUSIC_SUBSCRIPTION_CHECKOUT_MODE이며 기본 disabled다. test는 test_sk_ 키, live는 live_sk_ 키가 필요하다. 시간대는 서버의 MUSIC_SUBSCRIPTION_BILLING_TIMEZONE으로 지정하며 기본 Asia/Seoul이다. 사용자가 주문 요청으로 결제 모드나 시간대를 바꿀 수 없다.

현재 storefront checkoutEnabled는 false다. orderApiEnabled는 서버가 내부 결제 경로를 시험할 수 있는 모드인지 나타낸다. 프론트 구매 화면·실제 재생·환불·회계 검증을 마치기 전 운영 결제를 활성화하지 않는다. 이 변경은 운영 환경 변수를 수정하지 않는다.

## 주문과 결제 검증

- 상품가격은 서버의 24개 상품 정의로 결정하고 주문 생성 시 스냅샷을 저장한다.
- 같은 회원·요청키는 같은 주문을 반환한다. 등급·모드·시간대가 다르면 충돌이다.
- 동일 회원의 미해결 주문은 하나로 제한한다. 만료 주문은 승인 내역을 대조하기 전에 자동 폐기·다른 주문으로 우회하지 않는다.
- 해당 모드의 활성 구독이 있으면 새 구독 중복 구매를 막는다. 기간 중 등급 변경·예약 갱신은 별도 구현한다.
- Toss에 주문별 고정 Idempotency-Key로 승인 요청을 보낸다.
- 승인 실패·통신 중단 시 결제 조회 API로 이미 승인되었는지 확인한다.
- 주문번호·결제키·금액·통화 KRW·DONE 상태·승인 시각을 검증한다.
- 만료 주문은 신규 승인을 요청하지 않고 기존 승인 내역만 조회한다. 주문 유효기간 안에 승인된 결제만 복구한다.
- 서버 생성 시각은 밀리초, PG 승인 시각은 초 단위일 수 있으므로 동일 초의 정밀도 차이를 처리한다. 구독 시작은 주문 생성보다 빠를 수 없다.

참고: [Toss 결제 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow), [코어 API](https://docs.tosspayments.com/reference).

## 자격과 재원 기록

실제 승인 뒤 다음 항목을 동일 D1 배치로 처리한다.

| 항목 | 기록 |
| --- | --- |
| 주문 | confirmed 상태와 검증 결제키 |
| 영수증 | 실제 결제액·모드·승인 시각·자격 연결 |
| 창작자 재원 예산 | 결제액의 70% |
| 플랫폼 재원 예산 | 나머지 30% |
| 청취 자격 | 상품등급·시간대·시작·종료·원천 결제 |
| 구매 기여 | live만 paid_subscription 사건으로 기록 |
| 미해결 주문 슬롯 | 처리 완료 후 해제 |

4,900원 결제라면 권리자 재원 예산 3,430원, 플랫폼 재원 예산 1,470원이다. 이 숫자는 곡별 권리자에게 이미 지급한 현금이나 플랫폼의 확정 회계매출을 뜻하지 않는다. 실제 재생 배분과 회계 인식·세금·환불은 별도 연결한다. 시험결제 재원은 실제 현금으로 집계하지 않는다.

v5_music_orders, v5_music_order_slots, v5_music_receipts를 사용하며 일반 tl_payments 충전 영수증이나 지갑 계정을 만들지 않는다. 결제키와 주문·자격에는 고유 제약을 두고 재처리로 자격·점수를 중복 생성하지 않는다.

초기 이용기간은 승인 시점부터 UTC 기준 다음 달 같은 날짜·시각까지 1개월이며, 해당 날짜가 없는 달은 말일로 조정한다. 일일 포함시간 초기화는 자격의 현지 시간대로 계산한다. 자동 반복 결제는 구현하지 않았으며 autoRenew=false를 반환한다. 최종 상품약관과 주기를 확정한 뒤 출시한다.

## 검증과 남은 연결

실제 SQLite·HTTP에서 기본 비활성, 소유자·가격 위조 차단, 모드 일치, 시험 자격 제외, 영수증·자격·점수의 동시 롤백, 승인 조회 복구, 멱등성, 70:30 예산, 무발행, 말일·윤년을 검증한다. 실제 로컬 D1에서도 주문·영수증·재처리·시험 자격 제외를 확인한다. 외부 PG 요청은 검증용 대체 전송을 사용하며 실제 결제하지 않는다.

남은 연결은 구매 화면, 기존 플레이어의 구독 모드, 초과분 지갑 정산, 곡별 권리자 배분, 영수증의 현금 재무 보고·회계, 취소·환불·구독 변경, 최종 약관이다. 만료 미해결 주문의 조회 결과가 미승인일 때 안전하게 닫는 운영 경로도 추가해야 한다.


## 사용자 화면용 시험 설정 응답 후속

products 응답에 testCheckoutEnabled와 시험 공개 clientKey를 추가한다. 시험 모드·test_sk_ 서버키·test_ck_ 공개키가 모두 일치할 때만 시험 공개키를 제공한다. live 모드에서는 공개키를 내보내지 않으며 정식 checkoutEnabled=false를 유지한다. 상태 응답은 로그인한 본인의 userId를 포함해 세션 주문키를 회원별로 구분하도록 한다. 비밀키는 어떤 공개 응답에도 포함하지 않는다.
