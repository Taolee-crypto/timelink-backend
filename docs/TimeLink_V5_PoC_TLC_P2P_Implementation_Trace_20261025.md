# TimeLink V5 — PoC·TLC 공급·P2P 교환 통합 개발 기준 (2026-10-25)

## 확인된 코드
- frontend `public/wallet.html`: `GET https://api.timelink.digital/api/v1/users/me/wallet`의 `tlc_mineable`을 읽고 `POST https://api.timelink.digital/api/eco/mine-tlc`에 `tlc_amount`를 전달한다. **서버는 클라이언트 수량을 신뢰하지 말고 재산정해야 한다.**
- frontend `public/tl-tlc-pool.html`: 페이지 자체에 '거래 기능 준비 중'으로 표시된다. 실제 체결 완료로 간주하지 않는다.
- backend `src/index.ts`: `users.poc_index`, `total_tl_spent` 참조와 청취 시 `poc_logs` 기록 코드가 확인된다. PoC 실제 계산·TLC 발행 엔드포인트 전체 추적은 미완료다.
- backend `src/economy-ledger.ts`: V5 이중분개·멱등키·TL/TLC 자산을 다룬다.
- backend `src/v5-poc-reward-policy.ts`: 별도 기여도 평가 초안이며 실제 발행 경로와 연결되지 않았다.

## 정책 재정리
1. **TL**: 플랫폼 내 활동과 결제·청취·정산으로 발생하는 원장 자산. TL_A·TL_B의 환전 금지 규칙은 유지한다.
2. **PoC**: 검증된 기여도·활동 품질·중복 억제·계정 신뢰도를 평가한다. 단순 점수 자체가 자동 TLC 발행 명령이 되지 않는다.
3. **TILO (TLC)**: 별도의 자산 코드 TLC. 사전 고정 총량 일괄 발행을 전제로 하지 않는다. 다만 최초 유통 및 신규 공급은 기존 채굴·전환 정책의 코드·원장 추적을 거쳐 확정한다.
4. **P2P 교환 풀**: 회원 간 **실제 보유 잔액**만 에스크로로 교환한다. 교환은 신규 발행이 아니다. 가격은 체결 수요·공급에 따라 형성된다.
5. **가치 연동**: TL↔TLC 교환시장은 가격 발견 장치이지 가치 보장 장치가 아니다. 실제 거래 없이 시세를 생성하거나 수익률을 약속하지 않는다.
6. **관리자 통제**: 초기 보상·전환·수수료·거래한도 정책은 버전 관리 및 관리자 승인 후 적용한다.

## 기존 구현과 충돌하지 않도록 해야 할 작업 순서
1. `/api/eco/mine-tlc` 실제 서버 구현 파일·DB 쓰기 경로 추적. 클라이언트가 보낸 `tlc_amount`를 그대로 지급하는지 확인.
2. `tlc_mineable` 산식, `poc_index`, `poc_logs`, 소비량 기준과 월별 중복 산정 여부 확인.
3. 기존 TL→TLC 공식 전환과 P2P 풀을 구분하고 기존 주문/풀 테이블 여부 확인.
4. 기존 TLC 공급 내역과 V5 원장 TLC 잔액 간 대조; 신규 발행 경로는 단일 원장으로 통일.
5. 보상 안전 장치: 중복 이벤트 제거, 동일 대상 제한, 실재 청취 검증, 계정군·자전거래 탐지, 월별/회원별 상한, 정책 버전 기록.
6. P2P 주문·에스크로·취소·부분체결을 V5 원장 원자적 분개로 구현. PoC 점수와 시장가격을 혼합하지 않는다.
7. D1 통합 테스트, 원장 대조, 감사 해시·TON 앵커링 검증 후 운영 활성화.

## 현재 확인 한계
GitHub 코드 검색에서 `mine-tlc` 엔드포인트 구현 파일을 특정하지 못했다. 따라서 과거 채굴 산식을 실제 운영 산식으로 확정하지 않으며, 새로운 발행·교환 로직을 임의 활성화하지 않는다.
