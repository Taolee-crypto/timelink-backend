# TimeLink V5 TLD 악보 파일 · LOVE CODE VIEWER — 구현 계약

**기준일:** 2026-10-29
**구현 상태:** TLD 컨테이너 및 LOVE CODE 코어 계약 구현/CI 검증 중. 운영 자산 발행과 실제 VIEWER 로그인·권한·정산 연동은 미구현이므로 완료로 표시하지 않는다.

## 최종 파일은 PDF가 아닌 TLD
악보의 최종 배포물은 .tld 파일이다. 곡에 연결된 구조화된 ScoreData(음표, 음길이, 박자, 조표, 가사, 기타 코드)와 A4 페이지 레이아웃, 권리·출처·버전을 암호화된 TLD 컨테이너로 묶는다. MusicXML은 내부 편집/검수용 중간 파일일 수 있지만 PDF, 원시 MusicXML 또는 JSON을 최종 배포물로 공개하지 않는다.

## TL3 V5와 공유하는 변환 기술
- TLNK 매직 4바이트, 버전 0x05, 4바이트 BE 길이, JSON 헤더, AES-256-GCM ciphertext
- 헤더를 AAD로 인증하고, 암호문 내부에 매니페스트 길이/매니페스트/음표 데이터를 저장한다.
- 서버에 등록된 SHA-256 해시와 실제 TLD의 해시를 비교한다.
- 동일한 기존 Cloudflare TL3_MASTER_KEYRING, TL3_MASTER_SECRET 및 P-256 Viewer 키 전송 구조를 공용 기반으로 쓰되 TLD 용도는 도메인 분리한다. 기존 암호화 마스터키는 생성·교체·삭제하지 않는다.
- profile=TLD-V5, content_type=score로 TL3 오디오와 구분한다.

## LOVE CODE: 파일과 VIEWER가 만나는 순간의 상호 인증
LOVE CODE는 파일에 미리 써 넣는 고정 문자열이나 우회용 비밀번호가 아니다. 서버는 기존 마스터 시크릿으로부터 TLD LOVE 전용 도메인 HKDF/HMAC 키를 도출하여 자산 ID, TLD 해시, 사용자 ID, Viewer ID, Viewer P-256 키 지문, 세션 ID, 이용 정책, 난수 nonce, 만료 시각(최대 10분)을 결합한 검증 코드를 발행한다. 코드 검증은 서버에서 수행한다.

VIEWER의 실제 개방 절차:
1. 회원이 VIEWER에 로그인하고 .tld 헤더를 읽는다.
2. VIEWER는 서버에 파일 해시·자산 ID·자신의 P-256 등록 공개키 지문을 전달한다.
3. 서버가 파일 등록·권리 확인·이용권·기기 폐기 여부를 검사하고 일회용 nonce를 D1에 저장한다.
4. 서버가 짧은 유효기간의 LOVE CODE를 발급한다.
5. VIEWER의 응답에서 LOVE CODE·등록 기기·세션을 검사하고 nonce를 D1에서 원자적으로 한 번만 사용 처리한다. 단순 MAC 검증은 재전송 방지가 아니다.
6. 검증이 성공할 때에만 공통 TL3 P-256 ECDH/HKDF/AES-GCM 라이선스 방식을 통해 TLD 자산 키를 해당 VIEWER에 묶어 전달한다.
7. VIEWER가 복호화된 ScoreData로 A4 오선지와 가사 및 기타코드를 표시한다. 사용자가 실제 보는 것은 HTML/캔버스 악보이며 PDF가 아니다.
8. 서버는 열람 이벤트를 검증하고 확정된 시간·권리 정책에 따른 정산을 기록한다. TLD 요금 정책이 미정인 동안 TL3 청취 과금을 임의 복사하지 않는다.

## 현재 구현된 것과 남은 것
이번 PR에는 서버 전용 TLD 바이너리 codec, 암호화/해시 라운드트립, LOVE CODE 발행·검증 코어, 변조/다른 파일/VIEWER/회원/세션/유효기간 거부 테스트가 포함된다. 테스트에는 운영 키를 사용하지 않는다.

**운영 통합 전 필수 개발:** TLD 제조 API 및 발행 승인, score 자산 테이블/R2 등록, 기존 키 링을 통한 TLD 자산 키 봉인·키 ID, D1의 one-time nonce 소비, 기기 인증과 라이선스 P-256 키 전송, VIEWER 어댑터, TLD 열람·정산 정책 및 E2E 테스트. 코어 계약을 구현한 것만으로 운영 TLD 발행·VIEWER 작동이 완료됐다고 주장하지 않는다.
