# TimeLink 통합 TL 원장 전환 설계

작성일: 2026-10-21
상태: 설계 및 구현 기준 초안. 운영 원장 변경·초기화·배포는 수행하지 않음.

## 목표

기존 `users.tl`, `tl_balance`, `tl_p`, `tl_a`, `tl_b`, `tl_user_files` 및 개별 기능의 직접 잔액 갱신을 새로운 V3 append-only 원장으로 단계적으로 대체한다. 화면은 원장 조회 API만 사용하고, 거래 발생은 도메인별 명령 API를 통해서만 기록한다.

## 절대 규칙

1. TL은 정수 단위이며 1초 이용 = 1 TL = 1원 기준을 유지한다.
2. 일반 지갑 잔액과 자산별 이용 전용 잔액은 별도 계정이다.
3. 트랙 충전은 일반 지갑에서 해당 트랙 전용 풀로 이동하는 내부 이체다. 플랫폼 전체 TL 총량을 새로 발행하거나 소각하지 않는다.
4. 재생은 해당 트랙 풀에서 실제 재생된 초만큼 차감한다. 일반 지갑은 재생 중 절대 다시 차감하지 않는다.
5. 일시정지, 버퍼링, 건너뛴 구간은 과금하지 않는다. 중단 시 실제 재생분만 정산하고 잔액은 트랙 풀에 남긴다.
6. 재생 시작 시 기존에 동작하는 재생 가능 횟수 차감은 유지한다. 신규 원장 작업으로 중복 차감하지 않는다.
7. 재시도, 중복 요청, 세그먼트 재요청은 동일 idempotency key로 한 번만 반영한다.
8. 광고, 미션, 관리자의 지급·회수, 결제 충전, 창작자 보상, 광고 예산 에스크로, 환급은 같은 TL 원장에 거래 유형과 출처를 구분해 기록한다.
9. TLC는 별도 자산코드와 별도 원장 계정으로 유지한다. POC는 통화 잔액이 아니라 기여 기록으로 유지한다.
10. 과거 거래와 원천 테이블은 삭제하거나 임의 합산하지 않는다. 신규 원장으로 옮기는 값은 근거와 승인 기록을 남긴다.

## 계정 모델

- 사용자 공통 지갑: TL_P(유상·교환 적격), TL_A(광고 보상·교환 제한), TL_B(이벤트/보너스·교환 제한). 화면은 사용 가능한 TL 총액을 표시하되 각 출처별 세부 잔액도 확인할 수 있게 한다.
- 사용자 트랙 전용 풀: 사용자 + track/share ID 단위의 `track_pool` 계정. 오직 해당 자산의 이용 정산만 가능하다.
- 창작자 보상 계정: 지급 출처별로 유상/광고/보너스 성격을 보존한다.
- 플랫폼 수익/비용 계정: 광고 예산, 플랫폼 몫, 결제 수수료, 보상 재원 등을 구분한다.
- 에스크로 계정: 광고 예산·환급 대기액 등 사용 제한 자금을 분리한다.
- 시스템 발행/조정 계정: 관리자 초기 잔액 입력 및 승인된 정정 거래의 상대 계정. 사유·관리자·대상·증빙 필수.

계정의 실제 bucket 명칭은 코드 구현 시 현재 V3 스키마와 호환되게 고정하고 문서화한다. TL_P/A/B의 출처·교환 제한을 하나의 숫자로 합쳐 잃어버리지 않는다.

## 표준 거래 유형

| 거래 | 차변/감소 | 대변/증가 |
|---|---|---|
| 결제 충전 | 결제 정산/발행 상대 계정 | 사용자 지갑의 유상 TL |
| 광고·미션 보상 | 보상 재원 계정 | 사용자 지갑의 해당 출처 TL |
| 트랙 충전 | 사용자 지갑 출처별 TL | 해당 트랙 전용 풀 |
| 실제 재생 | 트랙 전용 풀 | 창작자 보상 + 플랫폼 몫 |
| 재생 취소/정산 정정 | 기존 수취 계정 | 원래 트랙 풀 또는 조정 계정 |
| 광고 예산 확보 | 광고주 지갑 | 광고주별 에스크로 |
| 광고 예산 사용 | 광고주 에스크로 | 광고 플랫폼 비용/보상 계정 |
| 관리자 지급/회수 | 시스템 조정 상대 계정 | 사용자 지정 지갑/풀 또는 반대 방향 |
| 환급/교환 | 사용자 유상 TL | 환급/지급 대기 계정 |

모든 거래는 TL 자산별 합계가 0이어야 하며, 잔액은 음수가 될 수 없다.

## 관리자 초기 잔액 입력

관리자 화면에 전환 도구를 별도로 둔다.

1. 기존 계정/테이블의 잔액을 출처별로 읽기 전용 미리보기한다.
2. 사용자별 기존 필드, 트랙별 충전 잔액, 보상·교환·결제 내역을 나란히 제시한다.
3. 서로 다른 필드를 자동 합산하지 않는다. 중복 가능성이 있는 잔액은 충돌 상태로 표시한다.
4. 관리자가 사용자의 공통 지갑 출처별 시작 잔액과 트랙별 전용 풀 시작 잔액을 명시적으로 입력한다.
5. 각 입력은 원천 테이블/행/필드, 입력자, 승인자, 근거, 체크섬, 시각, 전환 배치 ID를 남긴다.
6. 입력 확정 시 시스템 조정 계정과의 균형 거래를 append-only로 기록한다.
7. 같은 전환 배치/원천 행은 재실행해도 중복 적립되지 않도록 idempotency key를 사용한다.
8. 모든 사용자 합계 및 플랫폼 조정 계정이 대사되기 전에는 신규 원장을 운영 원장으로 전환하지 않는다.
9. 과거 원장/테이블은 감사용으로 읽기 전용 보존한다. 삭제/초기화는 하지 않는다.

## 화면/API 원칙

- 모든 사용자 화면의 TL 잔액, 트랙 전용 잔액, 거래 내역은 같은 원장 읽기 API에서 가져온다.
- 화면별 직접 계산, localStorage 잔액, 정적 숫자, users 테이블 잔액의 임의 fallback을 금지한다.
- 모든 화면은 로딩/오류/미초기화/정상 상태를 구분한다. 미초기화 상태를 0 TL로 표시하지 않는다.
- 지갑, 대시보드, 사이드바, Track, SharePlace, Creator, 방송, 광고, 미션, 관리자 화면은 동일한 잔액 정의를 사용한다.
- 관리자만 전체 사용자 원장과 조정 내역을 볼 수 있고, 사용자는 본인 계정만 조회할 수 있다.

## 구현 단계 및 안전 게이트

### A. 소스 전수 조사
모든 백엔드 잔액 쓰기 경로와 프런트엔드 TL 표시/충전/소비 API를 목록화한다. TL3 V5 암호화·세그먼트 포맷은 경제 라우팅 외에는 변경하지 않는다.

### B. 원장 서비스와 도메인 명령
기존 V3 append-only ledger를 기반으로 지갑 충전, 트랙 이체, 실제 재생 정산, 광고/미션 보상, 창작자 분배, 광고 예산, 관리자 조정 API를 만든다. 각 API에 권한 검사, 입력 검증, 멱등성, 원자성 테스트를 추가한다.

### C. 읽기 전용 관리자 대사 화면
기존 잔액을 자동 이관하지 않고, 사용자별/필드별/트랙별로 검토하고 입력하는 도구를 먼저 만든다. 미리보기와 검증 보고서가 먼저 통과해야 한다.

### D. 화면 연결
모든 화면의 잔액/내역을 공통 API로 전환한다. 페이지별 직접 잔액 수정 API 호출은 단계적으로 제거하되 기존 경로는 호환 기간 동안 감사/차단 정책을 둔다.

### E. 시험 전환
격리된 D1 테스트 DB에서 전체 계정·거래 시나리오, 재생 중단, 세그먼트 재시도, 중복 호출, 부분 잔액, 환급, 광고 예산, 관리자 입력을 검증한다. 운영 DB에는 쓰지 않는다.

### F. 운영 전환
최종 대사표를 관리자에게 제시하고 별도 승인을 받은 후에만 운영 전환한다. Cloudflare 배포와 운영 마이그레이션은 별도 명시 승인 없이는 하지 않는다.

## 완료 조건

- 어떤 화면에서도 동일 사용자/시점의 공통 지갑 잔액이 일치한다.
- 트랙 풀 잔액은 공통 지갑과 별도 표시되고 서로 중복 합산되지 않는다.
- 재생은 실제 재생 초만큼 해당 트랙 풀에서 한 번만 차감된다.
- 모든 TL 거래가 균형 원장에 기록되고 중복 요청은 재적용되지 않는다.
- TL_P/A/B의 출처 제한이 보존된다.
- TLC/POC 및 TL3 V5 재생·암호화 기능에 회귀가 없다.
- 전환 전후 잔액 대사 보고서가 일치하고 관리자 감사 로그가 남는다.
