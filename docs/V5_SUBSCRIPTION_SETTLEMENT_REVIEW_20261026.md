# 구독료 정산 검토 (2026-10-26)

실결제 영수증의 창작자 예산 70%와 회사 예산 30%를 관리자 전용 조회 API로 대조한다. 프런트엔드의 기여도·음악상품 관리에서 구독료 정산 검토로 이동한다. 시험결제, 결제키와 권리자의 전화정보는 노출하지 않는다.

`GET /api/admin/music-subscription-settlements?limit=25&offset=0`은 최대 100건의 실결제 영수증을 조회한다. `GET /api/admin/music-subscription-settlements/:orderId`는 해당 구독기간의 포함 청취 기록과 당시 권리자 스냅숏을 대조한다. 관리자 인증과 접근 이력은 기존 관리자 라우터를 재사용한다.

배분 방식은 **검토안**이다. 구독별로 창작자 원화 예산을 해당 구독자의 곡별 포함 청취 밀리초에 비례하여 배분한다. 지분까지 포함해 정수 원화의 나머지는 큰 소수 잔여 순서와 고정 식별자로 결정하여 예산 합계를 보존한다. 초과분은 이미 지갑 TL로 정산하므로 가중치에서 제외한다. 미청취 예산, 권리자 미확인, 구독기간 밖 사용량, 기존 정산 상태가 있는 기록은 보류한다. 업로더라는 이유만으로 구독료 배분의 권리자로 인정하지 않는다.

원화 예산을 TL로 바꾸는 비율을 임의로 정하지 않는다. 화면의 검토 예산은 TL 잔액 또는 현금 지급 가능액이 아니다. 확인된 권리자도 실제 수령 시점의 자격 재검증이 필요하다.

현재 지급은 항상 비활성이다. 사용기간 종료, 결제·환불 대조, 환불에 따른 예산 조정 기준, 원화-TL 정산 기준, 운영자 승인이 모두 남아 있다. 이 변경은 환불 API, 결제 취소, 원장 입금, 현금 지급, 채굴 지급을 실행하지 않는다. 조회를 반복해도 경제원장과 사용량의 미정산 상태가 바뀌지 않는다.

검증: 실제 SQLite와 관리자 HTTP 권한, 정수 배분과 합계 보존, 시험결제 제외, 초과분 이중 배분 방지, 취소·권리 확인 보류, 원장 미변경. 실제 로컬 D1에서도 포함시간과 보류 예산을 대조한다. 브라우저에서는 로그인·권한·금액 단위·안전한 텍스트 출력·오류 복구·빈 목록을 검증한다.
