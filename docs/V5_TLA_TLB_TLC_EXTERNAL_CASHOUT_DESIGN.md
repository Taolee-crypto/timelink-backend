# TimeLink V5 — TL_A / TL_B → TLC → 외부 거래소 정책 및 구현 계약

상태: **설계 확정 후보 / 실제 환전·전송 기능 미활성화**. 2026-10-23 논의 기준. 기존 채굴·재생·정산 기능을 변경하지 않는다.

## 사용자 의도와 자산 경계
- TL_P: 구매로 취득한 TL. 사용 시 TL_B로 전환되는 정책을 V5 경제원장과 정합성 검증 후 구현한다. 기존 70% 창작자 / 30% 플랫폼 재생 정산은 보존한다.
- TL_A: 광고 보상. TL_B: 청취·활동·기여 보상 및 정책상 전환분. **TL_A/TL_B 자체를 플랫폼이 원화로 직접 환전해 주지 않는다.**
- 이용자는 POC 기여 검증을 거쳐 TLC를 획득하고, 실제 TON 네트워크의 검증된 TLC Jetton을 자신의 TON 지갑으로 출금한 뒤, **실제로 TLC 입금·거래를 지원하는 외부 거래소가 존재하는 경우에만** 그 거래소에서 스스로 매도한다. 거래소 상장, 매수 유동성, 원화 지급 및 가격은 보장하지 않는다.
- V5 원장 내 TL, 내부 채굴 표시 TLC, TON 온체인 TLC는 별도 잔액과 상태로 취급한다. 내부 잔액만으로 온체인 출금 가능하다고 표시하지 않는다.
- TLC↔TL P2P 교환 및 에스크로는 별도 선택 기능. TON 주소는 TLC 수령용이며, 내부 TL 수령에는 TimeLink 계정이 필요하다.

## 가장 먼저 확정할 경제 정책
1. **소각형**: TL_A/TL_B 잔액을 차감하고 정해진 전환식으로 TLC 발행, 또는 **기여채굴형**: TL_A/TL_B의 검증된 사용·기여 이력을 근거로 TLC를 추가 채굴. 두 방식을 동시에 적용하여 동일 보상을 중복 발행하지 않는다.
2. 기존 `src/economics.ts`의 TLC 채굴식: `(월 TL_P 소비/30) × 0.08 × POC지수 × 플랜배율`, 일별 `min(계산량, 월소비×0.30/30)`. 기존 공식은 TL_A/TL_B 소각 전환을 구현하지 않는다. 전환율, 소각 여부, TL_A/TL_B의 POC 기여계수는 관리자가 명시적으로 승인할 때까지 미정이다.
3. 관리자 초기 공시 TLC/TL 환율은 보수적 가정(검토 시작점: **100 TLC = 1 TL**, 확정값 아님). 추후 주기적 단일가격 경매 도입. 내부 P2P 교환율과 외부 거래소의 TLC 시장가격은 별개다.
4. P2P 에스크로 수수료는 체결 성공 시에만 징수. 검토 시작점 1%, 확정값 아님. 수수료, 경매 공급량, 채굴 계수, 한도는 관리자 수동 조정·승인·감사 이력을 갖춘다.

## 구현 단계와 안전 조건
### 1단계: V5 원장 및 채굴 실태 감사
- `src/economics.ts` 레거시 `users.tlc_balance`와 V5 `v3_economy_accounts` TLC 잔액의 관계, `/api/eco/mine-tlc` 경로, 프런트 호출 경로, TL_P→TL_B 사용 시점, 월 하드캡 실제 동작 검증.
- 보상 출처, 채굴 근거 이벤트 ID, 채굴/전환 정책 버전, 환산율, 발행 총량, 환전 적격 여부를 별도 기록.
- TL_A/TL_B 사용·차감과 POC 채굴 사이 이중 보상·재진입 방지. 잔액 음수 금지, idempotency, 원장 대차 일치.

### 2단계: 통합 지갑
- TL_P/TL_A/TL_B/환전 적격 TL과 TLC(내부·온체인 구분) 표시.
- TON Connect 서명으로 지갑 소유권 확인. 사용자 개인키·시드문구를 서버에 저장하지 않는다.
- 공식 TLC Jetton master 주소와 decimals, 출금 수수료·네트워크 비용, TON 지갑 주소 형식을 검증. 검증되지 않은 자산은 입출금 차단.

### 3단계: TLC 출금
- 사용자 요청 → 보유 TLC 예약/잠금 → 온체인 서명·전송 → 블록 확정 검증 → 원장 완료. 실패·타임아웃은 중복 지급 없이 재처리/반환.
- tx hash, Jetton master, 수신 주소, 수량, 네트워크 비용, 상태, 감사 기록 저장.
- 외부 거래소에 대한 직접 원화 지급·환전 약속 금지.

### 4단계: 선택적 TLC/TL P2P 에스크로
- 양측 자산 확보 전 체결 완료 처리 금지. TON 입금 검증, 주문 잠금, 취소·분쟁·재시도·중복 체결 방지.
- 내부 TL 이전은 V5 원장 원자적 처리. TON 전송과 D1은 원자적 트랜잭션이 불가능하므로 상태 머신·보상 처리·최종성 검증 필요.
- 수수료 원장 별도 계정, 체결 후 부과. TL 출처 및 현금 환전 적격 상태를 세탁하거나 임의 승계하지 않는다.

## 출시 차단 조건
- TLC 실제 발행 및 온체인 Jetton 정합성 미검증
- 거래소의 실제 TLC 지원·입금 정책 미확인
- 가상자산 발행/중개/수탁·자금세탁방지 등 관할 규제 검토 미완료
- 이중 발행, 출금 재시도, 중복 정산, 수수료 누락에 대한 테스트 미통과

이 문서는 구현 계약이며 사용자 잔액·환전 권리를 자동 변경하지 않는다.
