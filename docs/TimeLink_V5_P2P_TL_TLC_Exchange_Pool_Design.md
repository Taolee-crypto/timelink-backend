# TimeLink V5 — P2P TL↔TLC 교환 풀 설계 초안

상태: 설계 초안. 운영 교환/발행 기능은 아직 활성화하지 않는다.

## 1. 경제 원칙
- TLC(TILO)는 PoC 점수에 따라 자동 발행하지 않는다. PoC는 기여도를 평가한다.
- 회원 간 교환 풀에 예치된 **실재 잔액**만 거래한다. 풀 거래는 TLC를 신규 발행하지 않는다.
- 발행 상한이 없다는 뜻이 무제한 발행을 허용한다는 뜻은 아니다. 신규 공급 규칙은 별도 거버넌스로 정한다.
- 플랫폼은 고정 가격, 가치 상승, 환매 보장, 수익률을 약속하지 않는다.
- TL_A 및 TL_B는 기존 환전 금지 정책을 유지한다. TLC 교환 가능 여부는 명시적으로 승인된 TL 자산/버킷에 한정한다.

## 2. P2P 풀 모델
- 1차 권장안: 중앙 경제원장의 **회원 간 지정가 주문 + 에스크로** 방식. 가격 형성 및 체결 기록을 명확하게 감사할 수 있다.
- 주문 생성 시 회원의 사용 가능 잔액을 에스크로로 이동/잠금하고, 체결 시 원자적 분개로 TL·TLC 소유권을 교환한다.
- 부분 체결, 주문 취소, 만료, 동시 체결, 중복 요청, 수수료, 환불을 각각 원장 이벤트로 남긴다.
- 교환은 반드시 양방향 실재 잔액을 확인하고, 음수 잔액과 초과 체결을 거부한다.
- 호가와 체결가격은 수요·공급에 의해 결정된다. 거래량이 작을 때의 시세 조작과 자전거래를 탐지한다.
- 유동성 공급형 AMM은 별도 단계에서 검토하며, 자동 시장조성의 가격 조작·무상손실·준비금 리스크를 먼저 분석한다.

## 3. 경제원장 불변 조건
1. 동일 거래의 TL 차변/대변 합계는 0, TLC 차변/대변 합계도 0.
2. 매칭 엔진은 코인 발행 권한을 갖지 않는다.
3. 미체결 잔액은 에스크로에 남고, 취소 시 원 소유자에게 반환한다.
4. 각 주문·체결·취소는 고유 멱등키를 갖고 V5 감사 아웃박스에 기록한다.
5. 교환 수수료는 관리자 승인 버전의 규칙으로만 변경한다.
6. PoC 점수는 발행 수량이 아닌 자격/우대 한도에만 연결한다.

## 4. 관리자 제어
- 기본값: 교환 비활성화(fail-closed).
- 허용 TL 버킷, 회원별 거래 한도, 최소 주문 단위, 수수료, 가격 이탈 경보, 일일 전체 거래량 제한을 관리자 콘솔에서 설정.
- 정책 변경에는 승인자, 적용 시각, 변경 이력, 이전 정책 버전을 기록.
- 의심 거래 시 주문/풀 일시 정지 및 원장 대조 기능 제공.

## 5. 운영 전 필수 결정
- TLC의 최초 유통분이 어디에서 공급되는지(기존 보유분/명시적 발행 사건).
- 어떤 TL 버킷이 교환 가능한지 및 교환의 법적·회계적 성격.
- 주문장 방식과 AMM 방식 중 출시 범위.
- 국가별 자금세탁방지, 이용자 보호, 가상자산·전자금융 규제 검토.
- 실제 거래 없이 임의의 TLC 가치가 생성된 것으로 표시하지 않기.

## 6. 구현 순서
1. 현행 V5 원장 자산·버킷·TLC 채굴 코드 정밀 추적.
2. 교환 가능 잔액 규칙과 관리자 정책 테이블.
3. 에스크로 주문·취소·부분체결 원자적 분개 및 동시성 테스트.
4. 자전거래·가격조작·과도한 보상 통제.
5. 감사 머클 배치와 연결, TON 앵커링 검증.
6. 관리자 승인 후 제한적 운영.
