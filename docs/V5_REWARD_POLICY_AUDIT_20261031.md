# TimeLink V5 보상규칙 현행 감사 및 폐기 적용 기록

기준일: 2026-10-31. 대상: 관리자 `/reward-policy.html`, `src/v5-reward-policy.ts`, `src/economics.ts`, `src/v5-ad-reward.ts`, 가입 지급 경로.

## 폐기 규칙 처리

- 광고주 전용 가입 추가 보상 `advertiser_signup_bonus`: 규칙 카탈로그에서 제거. 광고주로 등록되더라도 별도 추가 선물을 지급하지 않음. 기존 회원의 확정 보상은 취소하지 않음.
- 신규 광고 보상 `ad_min`, `ad_max`, `ad_default`: 규칙 삭제. `/api/eco/ad-session`, `/api/eco/ad-reward`는 HTTP 410으로 신규 지급 차단. `wallet_ad`와 과거 전표·감사 자료는 보존.
- 폐기된 악보 서비스의 `score_cap`, `score_share`, `score_use`, `score_view`, `weight_score`: 규칙 삭제. 레거시 PoC 계산에서 악보 점수/조회 제거. 4가지 현재 영역의 기본 가중치는 재생 40%, 유료 TL 소비 30%, 청취 20%, 업로드 10%.
- 이전에 DB에 저장된 폐기 규칙값은 **읽기 시 제외**하고 역사적 정책 JSON 및 변경 이력은 보존. 레거시 5요소 PoC 설정의 살아 있는 4요소는 기존 비율을 보존하도록 재정규화하며, 알 수 없는 임의 설정키는 거부. 실제 기존 사용자 지급분은 소급 재산정하지 않음.
- DJ, 영업매니저, 광고 기반 캠페인은 현행 보상정책의 새로운 지급원으로 재도입하지 않음. 다른 레거시 화면/엔드포인트의 완전 폐기 여부는 별도 전체 코드 경로 감사가 필요.

## 통과 조건 (코드 및 테스트)

- 폐기된 항목이 관리자 편집 정의에 없어야 함.
- 구버전 DB 설정으로 관리자 규칙 조회가 실패하지 않아야 함.
- 광고 보상 API가 신규 지급을 만들지 않아야 함.
- 악보 조회/사용/공유가 PoC 신규 계산에 참여하지 않아야 함.
- 가중치 합계 1, 부정확하거나 알 수 없는 저장 키는 거부, 관리자는 수동 버전 관리.

## 추가 검증에서 발견된 **미해결** 경제 규칙 위험

1. `src/economics.ts`의 오래된 `/api/eco/consume` 경로는 TL_B 소비에서 권리자 몫을 `tl_a`로 더함. 최신 출처 보존 원칙(비환금성 TL_B)과 불일치할 수 있음. TL3 V5는 별도의 실제 시간정산 경로가 있으므로 동일 거래의 이중처리 여부도 검증 필요.
2. `src/v5-cashout.ts`는 가입자의 누적 구매 비율 50% 및 원금환전 경로를 적용. **구매 TL_P는 법정 환불기간 경과 후 TL_B 전환**이라는 최신 결정과 양립하도록 시간별 잔액·환불·환전 정책을 재설계해야 함. 현금 책임과 과거 계약을 정리하지 않고 자동 변환하지 말 것.
3. `src/economics.ts` 채굴 계산식의 월 TL_P 소비 × 0.08 × PoC × 플랜B 2배는 TL-1~24 개별 시간 기반 채굴과 다른 모델. 동시 발행 방지, 활성 경로와 관리자 승인 상태의 운영 검증 필요.
4. 관리자 환전 수수료·가입 보너스·충전 보너스는 유지되지만 지급 준비금, 현금 정산대장, 환불 역분개, 실운영 교차검증은 이 변경만으로 완료되지 않음.
5. TILO의 실제 방송 초 × 0.3 TL × 권리자 70%/플랫폼 30%는 별도 원장과 계약 검증이 필요하며 광고/악보 폐기와 독립.
6. 추천 TL_B 및 POC는 검증 후 보상 규칙을 유지. 환불 역분개·자기추천 방지 및 다계정 검증은 별도 유지.
7. `src/economics.ts`에 기존 일반 MP3 업로드 PoC 분류가 남아 있으므로 TL3 보호 자산만 공개되는 현행 모델과 승인된 작품 기준을 대조할 필요가 있음.

**판정:** 폐기 기능의 신규 보상 정의/광고 지급 경로는 제거했으나, 전체 경제 규정의 실운영 적합성 **미검증**. 본 PR 병합과 배포 전/후 자동화·DB 경로 검증, 운영 데이터 기반 승인 필요. 폐기 이전 발생 금액과 장부 이력 삭제 금지.
