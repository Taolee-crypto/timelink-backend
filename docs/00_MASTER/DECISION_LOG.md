## DEC-001: 무료 콘텐츠 및 MP3 정책

### 현재 관찰
- 프런트엔드 `docs/IA.md`에는 무료 MP3 메뉴가 존재한다.
- 백엔드 `src/index.ts` 및 `src/routes/shareplace.ts`에는 MP3 업로드·무료 스트림·무료 POC 분기가 남아 있다.
- 프런트엔드 `public/creator.html`에는 TL3 고정 업로드 모드가 확인된다.
- 대표자의 최신 운영 방향은 TL 파일 중심이며 무료 콘텐츠를 제공하지 않는 방향이다.

### 결정이 필요한 내용
1. 기존 무료 MP3 데이터를 어떻게 처리할 것인가?
2. 기존 링크와 플레이어의 하위 호환을 유지할 것인가?
3. 기존 무료 콘텐츠를 TL3로 전환할 것인가, 신규 등록만 제한할 것인가?
4. 무료 콘텐츠에 부여되던 POC 및 통계 처리를 어떻게 할 것인가?

상태: 대표자 확인 대기.

## DEC-004: TL 단위와 잔액 원장

### 현재 관찰
- 코드에는 `tl_balance`, `tl`, `tl_p`, `tl_a`, `tl_b` 등 복수 잔액 필드가 사용된다.
- 일부 모듈은 `tl_balance`를 사용하고, 다른 경로는 세부 잔액을 합산한다.
- 과거 문서 및 구현에 서로 다른 초기 보너스·가치 기준이 존재한다.
- 최신 대표자 방향은 1 TL = 1원이다.

### 결정이 필요한 내용
1. 단일 기준 잔액 필드
2. TL 충전·사용·환불·창작자 수익의 원장 규칙
3. 소수 TL 허용 여부
4. 기존 잔액의 가치 환산
5. 거래 멱등성 및 이중 차감 방지

상태: DB/경제 코드 전수 조사 후 대표자 확인 대기.

## DEC-006: TL3 세그먼트 단위

### 현재 관찰

- 백엔드 MP3 프레임 분할 함수는 기본 targetMs가 5000으로 보인다.
- v3 빌더는 전달받은 segment 배열을 순회한다.
- 프런트엔드 플레이어는 응답 헤더의 세그먼트 길이 정보도 처리한다.

### 결정이 필요한 내용

3. 과금 단위와 암호화 단위의 관계
4. 온라인·오프라인 동일성

## DEC-008: TLC 채굴·Jetton 테스트넷 운영 상태

### 대표자 확인 사항
- TLC 채굴 시험 버전은 현재 작동 중이다.
- 이 시스템은 미구현으로 분류하지 않는다.
- 테스트넷 시험과 정식 메인넷 서비스는 별개의 운영 단계로 관리한다.

### 코드에서 확인한 구조
- `wrangler.toml`은 `TON_NETWORK = testnet`을 지정한다.
- `src/jetton.ts`의 `mintTLC`는 실제 온체인 민팅을 수행하지 않고 작업 식별자를 반환하는 큐 방식이다.
- `scripts/auto-mint.js`는 TON SDK를 이용해 testnet endpoint에 민팅 트랜잭션을 전송하는 별도 실행 경로를 갖는다.
- 출금 요청 테이블과 관리자 SQL API를 통해 대기 요청을 가져오고 상태를 갱신하는 구조가 스크립트에 포함되어 있다.
- 따라서 사용자 확인의 정상 시험 상태와 코드상 구성요소별 실행 경로를 함께 기록하되, Worker 함수 자체가 온체인 민팅을 완료한다고 오해하지 않도록 한다.

### 보안 및 운영 결정
1. 공개 저장소에 테스트 지갑 니모닉이 포함된 백업 파일과 자동 민팅 스크립트가 확인되었다. 해당 지갑은 비밀성이 이미 상실된 것으로 간주하고, 테스트넷 새 지갑으로 교체한 뒤 기존 지갑은 폐기한다.
2. 새 니모닉은 Git 저장소 밖의 로컬 비밀 저장소에서 관리하고, 스크립트는 환경변수 또는 로컬 전용 설정 파일을 읽도록 변경한다.
3. TON API 키의 테스트넷 전용 여부·권한·사용량 제한을 확인한다. 운영/메인넷 자격정보는 별도 Secret으로만 관리한다.
4. 시험 정상 작동 중인 기존 채굴 코드는 대표자 승인 및 재현 가능한 테스트 없이 수정하거나 비활성화하지 않는다.
5. 다음 단계에서 민팅 요청 생성 → 큐 저장 → 온체인 전송 → 트랜잭션 확정 확인 → 출금 상태 완료 처리 → 사용자/플랫폼 분배 비율을 통합 검증한다.

상태: 테스트 운영 중(대표자 확인), 키 교체 및 민팅 경로 통합 검증 필요.
